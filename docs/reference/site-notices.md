# 公告与页面更新提示

ON 控制台的“公告管理”支持保存草稿、预览、发布、撤回和删除未发布草稿。草稿与网站公开内容分别保存，修改草稿不会直接更新公告。时间按北京时间填写，留空表示立即生效或不自动结束。结束时间到达后浏览器自动移除公告，无需保持控制台打开。

工作台的“在哪些页面展示”支持多选，可搜索常用页面、资料查询、剧情和游戏工具，或添加自定义路径；“查看详情前往”仍选择一个跳转目标。编辑旧公告时，原来的单范围会作为一个选中项回显。显示范围包含所选路径的子页面，详情页面可留空，区服和语言由读者当前页面补齐。两项各有职责：展示范围不受详情跳转影响。例如选招募范围、版本记录详情，表示公告在招募及其子页面出现，公告详情面板内的链接前往版本记录。表单随区服、范围和详情选择实时展示完整说明；清空详情时仍可点击公告阅读正文。

时间栏整块可点击打开站点内日历，不依赖浏览器原生 datetime-local 的右侧小图标。支持年月切换、方向键选日、小时和分钟，以及“现在／1小时后／明天此时”快捷项；点击确定后才写入，取消或 Escape 保留原值。清空生效时间即立即生效，清空结束时间即不自动结束。全部时间固定按北京时间解释，跨浏览器时区不改变保存结果；结束时间不晚于生效时间时表单就地提示。

公告可投放全部区服、Global 或 JP，也可限定最多 32 个逻辑路径前缀。例如同时勾选“招募”和“活动”，两页及其子页面都会显示这同一条公告；匹配任意一个范围即可，多次匹配也只显示一次。选中“全站”会替换其他范围，改选具体页面则取消全站。选择面板按“确定”才写入，取消不改变原值。例如 `/` 为所有页面，`/my-growth/` 为养成页面，`/tools/` 为所有工具。详情链接同样填写逻辑路径，例如 `/updates/`；客户端保留当前区服和语言。标题与正文为纯文本，英文可选，缺少时显示中文。

普通提示可关闭，同一修订在此浏览器不再重复显示；维护和故障提示不可单独关闭，但可收起顶部公告并保留状态入口。重新编辑并发布新修订后，普通公告会再次展示。每站点最多保留 32 条草稿，已结束公告可先撤回，再删除草稿释放名额。第一版提供人工发布能力，尚未自动连接健康检查。

撤回和删除前如果有未保存的编辑，会先提示是否放弃修改。常用页面选项是维护的菜单配置，不会自动扫描新增路由；未列出的页面可使用自定义路径。工具页面的公告和更新脚本随公共界面立即加载，不等待工具数据准备完成。

通知采用本站纸色、墨色及莓红按钮。普通、维护、故障分别用蓝灰、赭色、莓红圆角标签区分，正文仍为常规阅读色。公告和更新均为独立的圆角单行提示条，配轻阴影。标识固定在左侧，标题和正文横向排列；超出可见宽度时自动往返滚动，悬停或键盘聚焦暂停，系统减少动态效果时不自动滚动。点击文字打开独立详情面板：桌面居中，手机位于底部；面板只展示完整标题与正文，有站内详情链接时在面板中提供。打开时暂停显示外部提示条，关闭后恢复单行，不在提示条内展开重复文本。更新提醒的刷新按钮为主操作，稍后弱化；操作始终固定在右侧。公告操作保留 44px 点击区域，更新操作按用户要求改为 32px 图标按钮，圆形底色 28px，保留悬停说明与可访问名称。控制台预览与站点公告采用同一视觉方向。

公告固定在导航栏下方，更新提示固定在底部，两者相对正文区域居中，正文不留占位。桌面最大宽度 560px，手机两侧保留 16px；默认每条公告为 54px、底部更新为 44px 高；多条公告区域最高 32dvh，详情面板内部可滚动。点击公告右上角的收起按钮或在公告内按 Escape，可收起为带状态和数量的入口；点击入口重新展开。当前标签页记住每条公告修订的收起状态，切页或轮询不会重复展开，新修订到达时重新展开。折叠入口旁的 × 可直接关闭当前普通公告；有多条时关闭当前可见的普通公告，维护和故障入口仍保留，新的修订会再次提示。更新提示独立显示，不随公告收起；普通公告的关闭与更新的稍后仍分别生效。

手机有配队工作台浮动入口时底部更新提示上移，打开 dialog 弹窗或手机导航时通知暂时隐藏，关闭后恢复。提示不锁定正文滚动、不自动抢焦点；收起和展开公告会把键盘焦点移到对应按钮。

## 节点与管理配置

程序对旧配置保持兼容，未配置时公告管理不可用。以下路径和身份均为部署示例。

在承载网站公开文件的节点配置中添加：

```json
"notices": {
  "directory": "/var/lib/ournotes-node/notices",
  "sites": ["ournotes"],
  "publishUsers": ["owner@example.com"]
}
```

在管理服务对应站点中添加 `"noticeNode": "resources"`，且该节点必须在站点的 `nodes` 中。对应节点添加 `"noticeUsers": ["owner@example.com"]`，并配置已有的 `readTokenEnv`、`writeTokenEnv`。BFF 和节点都检查发布人员，管理预览始终只读。此能力独立于资源生产 capabilities；R2 观察节点仍可维护公告，不恢复旧资源发布按钮。

节点服务沿用 `/var/lib/ournotes-node` 的写入权限。每站点存放：

- `drafts.json`：仅服务用户可读写，包含编辑人员和草稿。
- `public.json`：只包含已发布内容，原子替换，可由 Nginx 读取。

**只公开 `public.json` 的精确路径，不能给整个目录配置 alias。** 仓库的 `deploy/independent-content.locations.conf` 已给出 `/site-notices.json` 示例。确认 Nginx 用户能穿过父目录并读取公开文件；需要时仅对 `/var/lib/ournotes-node` 授予目录穿越 ACL，不能把 Nginx 用户加入可读取节点任务和凭据的服务组。草稿权限为 0600，公开文件为 0644，公告子目录为 0755。

新保存及发布的公告使用 `paths` 数组；节点与新版网站继续读取旧的单值 `path`，读取旧文件不做自动磁盘迁移，保存或重新发布时规范化为数组。发布前应交付支持多选范围的前端代码。

首次保存草稿不会生成公开文件；首次发布或撤回后会生成。文件未提供或暂时不可读时网站静默忽略，不影响资料加载。公开文件最后发布内容独立于节点和控制台运行，但节点停机时不能更新或撤回它；公告仍按结束时间失效。

## 更新提示

`/site-status/global.json` 与 `/site-status/jp.json` 分别读取网站当前预渲染目录的 `complete.json`。它们和公告均使用 `Cache-Control: no-store`。只公开完成回执，不能改为读取 R2 最新指针；后者可能仍在等待本机交付。未交付、文件不存在或校验失败时不显示更新提示。

页面在前台每三分钟检查一次公告和当前区服的完成回执，返回前台时也检查，最短请求间隔 15 秒，不重复并发。公告的定时生效和失效在前台最多延迟 15 秒，返回前台立即校正；网络失败保留已获取公告并继续按时间过滤。没有前台页面时不轮询。

将完成回执的代码和资料身份与当前页面固定身份比较，分别提示网站功能、当前区服资料或两者更新。当前快照不改变，计算和编辑不自动中断。点击刷新才进行正常重载，沿用浏览器未保存提醒；稍后仅对当前标签页中的同一目标版本生效。冷启动回退页可能比仍保留的 HTML 更新，首次检测到不同 HTML 组合时只记录基线，待交付变化后再比较，避免提示刷新到旧页面。

## 本地预览

独立预览支持 `--notices /PATH/TO/public.json`。提供 `--rendered` 时，只在回执匹配该预览实际代码和区服时返回更新状态，否则返回不可用，不伪造完成状态。

验证命令：

```sh
python3 -m unittest tests.test_site_notices tests.test_admin_analytics tests.test_admin_upgrade tests.test_admin_r2_delivery -q
python3 -m unittest tests.test_notice_delivery tests.test_preview_notices -q
node --test site/tests/site-notifications.test.mjs site/tests/startup.test.mjs site/tests/independent-content.test.mjs site/tests/prerender.test.mjs
bash scripts/build-web-client.sh --preview output/site-notices-preview
```

第二条命令需要允许绑定本机回环端口，用实际 HTTP 传输验收管理服务、资源节点与公开文件路由。修改后同时核对构建产物中的通知脚本加载时机。

发布后需另行验收：控制台保存草稿不公开、发布后旧标签页取得通知、定时结束/撤回、新版本页面可用后提示、计算中选择稍后不影响当前输入。新增前端代码未发布前，已经打开的旧页面不会凭空获得通知检测能力。
