# 内容生产与 R2 交付

Global／JP 在 GitHub 托管 runner 生产，R2 保存不可变内容，服务器组合已验证代码和内容生成 HTML。网页代码发布、游戏内容生产和官方更新档案分别交付。本文描述当前源码的操作契约；实际镜像、变量、定时器和最后成功版本应在操作前现场核对。

## 存储与身份

私有状态桶保存受信客户端、生产输入、配置、缓存和 checkpoint，绝不公开。公开内容桶也保持 bucket 私有，只通过只读 Worker 的允许路径提供浏览器内容。不要将私有状态桶绑定到公网 Worker。服务器仅持有公开内容桶的只读凭据；Actions 的写入凭据和归档模块的凭据分开管理。

区分四个状态：Actions 最后尝试、私有可恢复 checkpoint、公开内容指针、服务器实际交付的 HTML。前一步成功不代表后一步完成。两服共享目录的交叉引用必须保持一致；当前网页和旧标签页仍可能依赖历史内容。

## 调度与配置

源码的唯一原生 cron 为 `0 1,6,11 * * *`，即北京时间 09:00、14:00、19:00，每次检查两个已启用区服。同服串行，不取消正在运行的生产；一服失败不取消另一服。这是检查时点，不是交付时限。额外更新手动触发，不增加维护重试循环。

| 设置 | 用途 |
| --- | --- |
| `OURNOTES_UPDATE_IMAGE` | 经验证且固定 `@sha256:` 的生产镜像 |
| `CONTENT_R2_RUNNER_LABEL` | 可选托管 runner；按实际空间与峰值验证容量 |
| `R2_GLOBAL_CONFIG_PATH` | 私有配置的 ROOT 相对路径 |
| `R2_GLOBAL_STATE_PATHS` | 精确恢复路径 JSON 数组，与 checkpoint 选择一致 |
| `R2_GLOBAL_DECODER_PROFILE_PATH` | 位于选择范围内的可信外置 profile |
| `CONTENT_R2_ENABLED_GLOBAL` / `CONTENT_R2_ENABLED_JP` | 分服运行开关，未启用不运行 |
| `CONTENT_R2_AUTO_PROMOTE_GLOBAL` / `CONTENT_R2_AUTO_PROMOTE_JP` | 是否自动晋级，先完成 shadow 验收 |

真实值保存在受保护的环境。`content-r2-production` 的分支约束、Secret 名称和实际工作流应一起核对，不通过复制整份配置覆盖已有环境。旧快速轮询开关不改变当前频率。[外部触发器](external-trigger.md)是可选替代方案，不能与原生定时同时启用。

## 更新与晋级

1. 审阅源码并通过 CI。需更新镜像时运行 **Publish reviewed updater image**，核对摘要与源码身份后固定镜像；仅合并源码不会更新已固定的运行镜像。
2. 检查私有状态选择、可信客户端、解码绑定及 runner 可用空间。状态完整性与恢复语义见[私有状态契约](../reference/private-state.md)。
3. 从默认分支手动运行 `content-r2.yml`，选择单个区服和 `shadow`。它执行生产、不可变内容上传及读回、私有 checkpoint，不切公开内容指针。
4. 核对客户端签名、版本、候选封存、资源摘要、两服引用和空间峰值。获得对应发布授权后使用 `promote`；`auto` 按分服自动晋级设置处理。
5. 核对公开指针、服务器预渲染完成回执、两服两语言关键页面和真实浏览器。保存必要恢复身份到私有部署资料，不在本文追加现场日志。

无变化路径必须验证生产源码／配置／镜像、受信客户端和成功回执，并确认回执对应的公开指针仍有效。符合轻量门禁时跳过恢复和重生产；缺少回执或源变化转完整流程，探测失败不能伪装为无变化。指纹规则变化后的首次完整生产属于正常重新验证，不能绕过。

Global 升级先遵循官方推荐客户端、包签名和解码绑定，见[Global 解码器](../reference/global-decoder.md)。JP 见[自动升级](../reference/jp-client-upgrade.md)和[出口配置](jp-egress.md)。未知材料、版本拒绝或解码失败均保留旧公开内容。

## 健康与故障

运行回执只保存白名单阶段、运行身份和结果，不含步骤正文、凭据或原始 RPC。私有管理页分别显示远端运行、本地交付和榜单状态，见[管理页说明](../../deploy/admin/R2_DELIVERY.md)。

健康采样器须与 `tools/r2_schedule.py` 一起交付：按最近应到时点加一小时宽限判断陈旧，19:00 至次日 09:00 的正常间隔不告警。原生 schedule 时间与手动成功分开，后者不能掩盖定时未触发。采样过期显示不可用，不能复用旧成功。

初始告警策略为：回执／交付缺失或版本落后持续十分钟；连续两次运行失败立即告警，单次失败持续十五分钟；运行超过六小时告警。榜单陈旧与暂停独立判定。磁盘按真实发布预算判断，不套用某次历史剩余空间。修改阈值须同步配置与手册。

可选 Worker Analytics 仅使用专用只读凭据；未配置显示未配置。最近十分钟至少五次错误且错误率至少 1% 时告警，日请求预算需显式设置；采样量不等于账单。专用凭据与启用仍应核对[未结事项](../BACKLOG.md)。

编译失败诊断可能保存在私有桶，属于私有资料，不复制到公开 artifact。先查失败阶段与固定错误分类，再核对同一运行的镜像、状态和输入；不因后续诊断上传失败覆盖原故障。

## 恢复与回滚

计分模型升级后，若只需刷新歌曲排行榜，可从默认分支运行
`recompute-song-rankings.yml`。指定区服、当前 `current.json` 原始字节的 SHA-256、
与源码一致的模型版本，以及 `verify` 或 `promote`。此流程不访问游戏接口，
仅支持已经完成读回验证的 shared-media 快照；先验证完整内容清单、规则、谱面及媒体身份，
再重算两语言的普通／激奏榜单并检查覆盖率。`verify` 不写远端；`promote`
上传新不可变快照并读回，复用已验证媒体，以旧指针摘要和 ETag 条件切换当前指针。
新快照保留游戏内容身份，更新自身 URL 和清单摘要；旧快照、上一版指针和晋级日志可用于恢复。
该工作流与同服常规生产共用串行锁；指针变化、缺失输入或验证失败均停止发布。
发布后仍须执行上文的预渲染和线上页面验收，不能仅凭重算成功判定恢复。

失败上传或 CAS 冲突先重新读取当前指针，不强制覆盖未知新版本。保留当前／上一版代码、公开内容与 HTML 的引用闭包；回退前验证旧组合仍能访问资源。新代码回滚见[部署入口](../DEPLOYMENT.md)，HTML 交付见[预渲染手册](../../deploy/r2-prerender.README.md)。

旧本机内容生产管线已退役，不通过恢复旧 timer 或撤除 Worker Route 回退当前流程。历史迁移脚本和服务模板仅保留其受审用途，不代表允许重新启用。私有 checkpoint、公开内容和归档对象的清理均需各自的引用审查；运维操作见[容量与恢复](operations.md)，不执行整桶过期或全局 prune。
