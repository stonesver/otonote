# 抽卡记录与卡图分享

用户已确认：放在工具子模块，支持港澳台 BHK 邮箱登录；每次重新登录查询，只展示本次官方返回的记录，不在服务端或浏览器持久保存，不积累历史。支持导出带 SSR / UP 卡图的分享图片。比较 A 抽卡相册、B 统计面板、C 成绩单后，最终选择结合 A 和 B。

## 数据与边界

复用现有 BHK 登录、官方主机白名单与同源网关，新增独立的抽卡历史读取方法。只允许已核对的 History RPC，不开放抽卡、兑换或其他写接口。凭据仅在请求期间使用，响应不包含身份、密码或令牌；返回及代理响应使用 no-store。页面离开、刷新、重新查询或主动清空时销毁记录与分享图。登录可能使游戏会话失效，沿用现有提示。

静态客户端证据包含空 HistoryRequest、HistoryResponse 的旧版 history 和按批次 execution_history。优先使用带卡池、抽取方式和奖品列表的批次记录，两种结构不能相加。旧版记录缺少卡池时展示为未归属记录，不猜卡池。查询范围仅代表官方当前返回的数据，保留期限未知时明确说明。相同结果的真实批次不可因内容相同被去重。

历史奖品 ID 通过 MasterGachaPrize 对应成员卡、留影和道具；内容投影补充可选奖品映射，兼容旧快照。未知卡池和奖品保留记录并标为未识别，不纳入依赖完整识别的稀有度评价。客户端和真实账号记录对账属于不同验证阶段。

## 页面与分享

新增 /tools/gacha-history/，工具目录提供入口。页面包含 BHK 登录、查询范围提示、分池切换、总抽数及 SSR/UP 统计、稀有度分布、各池抽数、每日抽数趋势与批次记录。可以按日期、卡牌种类及稀有度筛选明细。只计算可证实的批次间隔；没有批内顺序证据时不显示精确的单抽序号或保底进度。

角色卡与留影独立统计，各自记录数作为稀有度占比的分母，包含保证抽取。图表区分非 UP、当期 UP 和 UP 未判定；当期指抽取时所属卡池，只有奖品属于该池奖品组且提供明确标志才判定。旧版或缺失资料不推断 UP。移除运气称号、概率评价及修饰性长文案，仅展示可核对的事实。零记录、全部未识别、请求失败及非港澳台区服均提供明确状态。

卡图相册展示 SSR / EX / BD 与已确认 UP 卡牌，同类同卡合并并标注总张数、UP 张数及未判定张数；角色卡竖排、留影横排，支持类型及 UP 筛选。分享图在浏览器用 Canvas 生成 PNG，每类最多展示六种卡，已确认 UP 优先，其他卡牌仍计入统计；图下保留两类独立图表。卡图只从同源内容资源加载，失败时回退缩略图，再保留卡名和数量。只使用统计模型的允许字段，不读取整页 DOM 或账号输入；不包含邮箱、账号 ID、凭据或逐条抽取时间。允许预览后下载，不自动发布到外部服务。筛选、清空、重新查询和页面离开时取消未完成的生成并销毁旧图。

## 视觉

沿用站点字体，采用白底卡片和轻边线。蓝色代表角色卡、青绿色代表留影、金色代表 UP、灰色斜纹代表未判定。顶部登录区在成功查询后收起；结果从筛选和四项概要开始，依次展示 B 的分栏统计、A 的卡图相册、分池与日期趋势、逐条明细。桌面相册并列展示角色卡与留影，手机纵向排列。数字使用等宽字体，图表配文字标注，控件可用键盘操作。分享图保持相同配色，以卡图为主、图表为辅。
