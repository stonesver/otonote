# 服装图鉴设计

日期：2026-10-03。用户已确认第一版采用独立服装图鉴、角色页关联入口、服装资料和现有 Live2D 预览。本文将该范围落实为数据、页面与验收约定。

## 目标与边界

用户可以从资料导航进入服装图鉴，按角色、乐队或名称查找游戏内可换装服装，查看获取条件、配置开放时间，并打开对应模型预览。角色详情页提供该角色的服装入口。

第一版以当前区服的内容快照为依据，支持简体中文与英文。同一套服装下的多个模型变体只计为一套。剧情造型仍保留在原 Live2D 工作台，不混入可换装服装图鉴。

本模块不管理账号衣柜、拥有状态或游戏内换装，不新增计分能力。开发与本地验收不包含生产发布。

## 已验证依据

2026-10-03 对线上国际服 1.0.2（versionCode 50）的公开内容清单进行摘要校验，并只读检查与发布绑定的原始主表和资源索引：

- `MasterCharacterCostumeGroup` 有 76 条分组，其中 `_isChangeable` 为真的分组有 26 条：25 套初始服装、1 套非初始服装。
- `MasterCharacterCostume` 有 102 条模型关联。26 个可换装分组关联 52 条记录，全部能按 `_live2dPath` 对应到已发布模型。
- 26 套图标都能在当前资源索引中找到，类型为 `UnityEngine.Sprite`；尚未验证服装图标实际导出与浏览器显示。
- 非初始服装关联角色 22、成员卡 64，名称为 `Birthday 26-27`；配置时间为 `2026/10/04 0:00:00`。这些是核查样本，不作为程序中的固定数据。
- 线上模型清单可用不等于实际播放已验收，浏览器播放作为独立检查。

现有 `tools/character_media.py` 提取的是模型级服装记录，缺少服装分组的名称、图标和获取条件。`tools/live2d_discovery.py` 按模型路径去重，故新模块不能假设主表记录 ID 必然等于发布后的模型 ID。

## 用户界面

新增逻辑路由 `/costumes/`，归入现有资料导航，并在资料首页添加入口。页面延续站点的卡片、字体与配色。

页面提供名称搜索、乐队筛选和角色筛选；筛选条件同步 URL，刷新及浏览器前进后退能恢复结果。角色筛选使用现有角色标识，乐队选择变化时清除不属于该乐队的角色。显示筛选结果数量、清除按钮和无匹配状态。

每张服装卡展示官方图标、服装名称、所属角色、初始／条件获取标识、获取条件和配置开放时间。点击角色或关联卡牌进入当前区服与语言下的对应详情。没有可靠获取关系时显示“获取方式待确认”，不根据图标、名称或相似卡牌推断。

模型以预览链接进入现有 Live2D 工作台，使用真实发布模型 ID 预选该套服装的模型。存在多个变体时列出可选预览链接；类型尚未确认时使用中性编号，不把 `_costumeType` 擅自翻译为画质等级。进入工作台后仍由用户点击加载，不在图鉴列表下载模型。

角色页新增“服装”入口与数量，链接到 `/costumes/?character=character-ID`。服装条目多时由图鉴完成浏览，角色页保持紧凑。

## 数据契约

新增独立投影 `costumes.json`，包含：

| 字段 | 约定 |
| --- | --- |
| `schemaVersion` | `1` |
| `contentReleaseId`、`region`、`locale` | 与当前投影一致 |
| `status` | `available` 或 `unavailable`；用于区分已有服装数据与缺少主表 |
| `costumes` | 只收录 `_isChangeable === true` 的分组 |
| 条目 `id`、`masterId` | `costume-group-ID` 与原始分组 ID；不以名称作为标识 |
| `characterId`、`bandId`、`name` | 从同一快照的角色关系和本地化文本解析 |
| `icon` | 导出成功时提供 URL、尺寸；缺图时为 `null` |
| `isInitial` | 原始初始获取标识 |
| `unlockMemberCardId` | 有效关联卡牌标识或 `null` |
| `startAt` | 原始配置时间字符串或 `null` |
| `models` | 主表记录 ID、原始类型码、模型路径、匹配的发布模型 ID 与可用状态 |

以分组表为图鉴入口，以 `_groupID` 关联模型表，再按模型路径关联同一发布的 Live2D 清单。校验重复分组 ID、角色引用、成员卡引用、分组与模型所属角色一致性。重复或矛盾关系应阻止候选产出，而不是静默覆盖。

文本沿用现有区服本地化规则；无名称时展示“服装 #ID / Costume #ID”。不得从其他区服读取服装、角色或卡牌来补齐当前区服的关系。

时间字段保留主表原值并标明“游戏配置时间”。是否“待开放”复用现有活动时间规则，仅在该区服的时间解释已有依据时计算；无法可靠解释时仅展示时间，不用访问者电脑时区作假设。预渲染中的时间状态必须在浏览器启动时刷新。

## 内容链路

1. 新建 `tools/costume_catalog.py`，负责分组、文本、解锁关联和模型关联的投影，保持可用合成数据单独测试。
2. 在 `tools/current_content_media.py` 增加服装图标提取，接入 `tools/current_content_inputs.py` 的模块缓存与校验清单。新模块源码纳入输入构建指纹，避免复用缺少服装图标的旧完成标记。
3. 图标按 Sprite 资源解析其纹理和裁切信息。现有 `CurrentResources.image()` 仅查找 Texture2D，不能直接沿用。对同键的 Sprite／Texture2D 必须精确选择资源类型；保留游戏路径中的空格和拼写，不自行纠正。输出文件名使用数字分组 ID 与内容摘要，避免把原始路径直接用作文件名。
4. 图标置于独立 `public/costumes/` 目录，生成带摘要的资源清单。缺少图标索引或不支持的格式可记录为不可用；已声明文件的摘要损坏必须报错。
5. `tools/release_candidates.py` 从已绑定主表、图标清单与 Live2D 清单生成每个语言的 `costumes.json`，拷贝服装媒体并纳入候选清单；历史输入缺少新模块时仍可构建明确的不可用或缺图投影。
6. `tools/content_publication.py` 支持服装媒体目录和 URL 重写，继续使用不可变快照、摘要验证及引用存在性检查。新投影进入现有文件清单，不引入实时后端 API。
7. 内容更新的缓存身份需包含新投影与图标提取逻辑，确保同一资源版本在程序升级后能生成新候选；不得手改已经封存的快照。

如日服管线复用该提取接口，仅接入相同契约及缺表回退，不扩展跨服合并功能。

## 页面与旧快照兼容

新增服装数据访问层、筛选逻辑与 `/costumes/index.astro`，沿用现有区服链接规则。导航、资料入口、角色入口、中文与英文文案一同更新。

独立网页运行时以可选投影加载服装资料。旧快照没有 `costumes.json` 时，服装页显示“当前版本服装资料待补充”，角色页不显示虚假数量；不因新增模块导致既有页面加载失败。

仅清单中缺少可选文件可以回退。文件已经声明但网络读取失败、摘要不符或版本不一致时，显示现有内容错误状态，不把故障伪装成空数据。独立构建、数据依赖清单与预渲染都必须识别该可选契约。

已有服装表为空时显示“当前版本暂无可换装服装”，与缺少投影、筛选无结果区别显示。模型不可用时保留服装资料并说明预览待补充；图标不可用时使用文本占位，不显示破损图片。

## 验证与交付

- Python 合成样例覆盖：同组多模型只计一套、过滤不可换装分组、本地化与缺名、初始服装和卡牌解锁、缺表、无模型、重复 ID、错误关联、Sprite 提取与裁切、资源清单摘要及旧输入回退。
- Node 检查覆盖：组合筛选、URL 恢复、空态、时间状态、正确的模型预选链接、区服与语言保持、可选投影缺失及完整性失败。
- 候选与发布集成检查覆盖：服装投影随内容发布、媒体 URL 重写、摘要与引用验证；旧内容仍能加载角色页和服装页。
- 独立代码构建不依赖真实游戏包。功能完成后执行相关测试及构建检查；官方候选遵循仓库既有门禁。
- 本地浏览器使用与真实快照绑定的服装投影，检查中文／英文、桌面／手机宽度、键盘筛选、角色入口、卡牌跳转、返回恢复和一套常规／生日服装的预览。图标应检查实际裁切结果，不能以索引存在替代验收。
- 更新 `docs/USER_GUIDE.md` 与必要的技术说明。交付报告区分源码验证、本地真实内容验收和生产发布，标明任何未完成项。

## 规格自检

范围、标识、缺失数据、发布完整性和测试边界已经明确。首版不依赖新后端；不硬编码本次核查的 26 套数量、生日服装或开服时间；没有未定字段或待选界面方案。
