# Actions 与 R2 内容迁移实施计划

依据：[设计](../designs/2026-10-05-actions-r2-content-design.md)。目标为 Global、JP 两服的 GitHub 托管 runner 自动生产与 R2 发布，现有站点继续提供网页。

## 1. 发布协议与离线测试

- 将内容封存与指针切换分开。封存产物仍采用现有 24 位 release ID 和 `/content/releases/` URL。
- 实现只上传公开清单允许对象的 R2 发布器、不可变 key 校验、晋级记录和条件指针切换；提供 `--dry-run` 与合成对象存储测试。
- 实现只读内容网关，限制路径、方法和缓存行为；提供本地请求测试。

完成标准：旧网页能读取新快照，冲突或中断不改变线上指针；回退只选择已经验证存在的 release。

## 2. 生产状态持久化

- 定义私有 R2 输入清单及阶段回执。在固定的 `/srv/ournotes-updater/app` 恢复根下兼容现有绝对路径回执；恢复与复用时重验每个文件的摘要。
- 实现基线导入、按需恢复、断点续跑与失败诊断；保留当前服务器状态，迁移工具只读取和复制它。
- 用真实 Global 工作集记录 runner 磁盘峰值、内存与耗时；据结果确定标准还是大容量托管 runner。

完成标准：一个全新 runner 能恢复已验证输入，重复运行结果一致，缓存损坏会拒绝复用。

## 3. Global Actions 流水线

- 固定运行镜像和依赖，接入官方包发现、签名、资源同步、编译、内容封存及 R2 发布。
- 加 `schedule`、人工重试、区服并发控制和最后成功时间监测。PR job 无生产凭据。
- 先影子运行，后在明确验收后启用自动晋级。

完成标准：上游不变时跳过、变化时产出并晋级、任何失败时保留旧指针。

## 4. JP Actions 流水线

- 将固定 1.0.4 / 2026-09-30 的输入构建器改为从经签名验证的客户端 profile 与官方版本观测中取身份；把手机目录依赖换成受校验的 CDN/包输入适配器。
- 实现自动版本探测、Master/资源采集与完整性校验、输入构建、投影和 R2 发布。新客户端版本、签名或解码结构未知时停止并报警。
- 使用与 Global 相同的状态、封存、晋级协议，区服指针独立。

完成标准：当前受支持客户端版本内可无人值守追新；新客户端版本被安全阻断且不影响旧内容。

### 真实 runner 暴露的历史输入遗漏

JP 影子运行 `37257554499` 在候选编译阶段因缺少 `catalog/evidence/arena-client.json` 停止，未晋级。该文件原为旧仓库提交 `8cb472c6533bfcfb618cd54fa0168cee11489d2a` 跟踪的静态审阅数据，源码导出时被整个 evidence 目录的排除规则遗漏。恢复原始字节（SHA-256 `2fa9fc8a8ba121b4fcbb486a4f2b88d6dcf1754720ad1dfe2371740387a8bfb0`），仅对该文件开放源码及镜像选择，并将其纳入两服候选指纹和 CI 检查。

旧 Global、JP 封存内容使用同一份历史结构证据；恢复它是保留现有行为，不是新版本的独立取证。不得据此宣称当前区服开关或实时赛季已开放。缺失或不合格证据仍须阻断构建，不能用空投影绕过。

## 5. 网站与预渲染切换

- 在现有橙云代理主机名的 `/content/*` 挂只读 Worker Route；保留旧 Nginx 别名供移除 Route 后回退。其他路由不改。
- 预渲染从固定 R2 快照物化必需文件并校验，发布 HTML 时再次比对内容/代码配对。
- 验证四个语言入口、跨服资料、图片/音频/Live2D、浏览器摘要校验、动态服务隔离。

完成标准：站点仍由原服务器提供，内容由 R2 提供，页面与预渲染没有混用版本。

## 6. 生产交接

- 由站点所有者创建 R2 bucket、现有域名的 Cloudflare Worker Route 及 GitHub 环境 Secrets；仓库提供所需变量与权限清单。
- 真实 R2 影子上传和读回、真实 runner 容量测试、生产切换与回退演练分别留验收记录。
- 确认新任务已稳定运行后停用旧内容定时器；旧历史数据只经独立审计维护。

完成标准：两服生产任务定时运行；最后尝试、最后成功、阻断原因可观察；回退指令已在真实部署上演练。
