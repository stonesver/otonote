第二轮已完成。相对上一轮，主要搜索路径的墙钟加速比中位数为 **1.96～2.89 倍**，CPU 加速比为 **2.00～3.43 倍**，结果与证明能力保持不变。全卡库差分、700 张谱面的完整验证、全部 24 张挑战的三版本对照均通过。内存并未全面下降；相对最初版本，2 张挑战谱面的墙钟仍略慢，具体列在下文。

## 实现与等价性约束

本轮延续[上一轮结果](2026-10-10-calculation-algorithms-results.md)的搜索与证明能力，优化公共计算内核。候选预算、技能顺序数、玩家样本、浮点精度和最优性判定条件保持不变。

1. **紧凑匹配网络**：对象残量边改为数字数组及反向边索引，距离、前驱和队列标记使用可复用数组；保持图的插入次序、增广顺序和严格比较规则，并列队伍选择不变。
2. **回放减少分配**：分数桶使用数字索引；没有因子指令的桶不再分配零差值对象；只取分数时避免复制全部音符。仍执行原生 float32 差值撤销、迟到指令和倒查逻辑。
3. **复用有效技能时序**：对相同谱面和有效指令序列，记住原生回放得到的每个音符最终因子。不同卡组使用当前战力重新逐音符计算分数；无记分适配器时，同权重、同连击因子的音符共享记分查表。首次出现的时序仍执行完整回放。因子缓存仅在单个计算器内有效，上限为 512 项且数组载荷不超过 4 MiB；键和 Map 本身另有开销。音符/固定分适配器、明细轨迹继续走原生路径。
4. **减少配对准备工作**：成长 Master 表按原始字段类型建立两层索引，保留首行匹配和类型校验；单槽入口保留成长与阵容合法性检查，复用原有算术，省去无关槽位和全队报告计算。一个优化任务的实用种子与精确搜索共享相同输入的配对矩阵，任务结束即可释放。

本轮没有减少搜索范围来换速度，也没有修改页面组件。所有效果结论均限定在当前计算模型和验证输入内。

## 数据与测量方法

使用上一轮于 2026-10-10 02:46:57（Asia/Shanghai）冻结并校验的发布数据，以确保同输入对照：国际服 67 张成员卡、69 张留影、352 张谱面；日服 67、68、348。两服独立计数，共 700 张谱面。发布 ID、规则及谱面摘要保留在机器报告。

- 所有搜索使用对应服全卡库。谱面基准成长固定为等级、突破、开花及两类技能等级均为 1；单队回放轮换卡组覆盖全卡。卡库差分另遍历成长配置及技能等级，不把这等同于所有成长的五人队穷举。
- 普通回放包括理想判定的 120 顺序、steady 的 3 样本 × 120 顺序。激奏包括理想判定全顺序和 steady 固定顺序，随机批次为 2。
- 战力搜索无候选预算限制；期望分搜索为 20 候选。活动沿用 `eventId=2`、普通收益 `includeChallenge=false`，挑战使用该活动允许的 24 张谱面。CP 规划单独测量。
- 串行三版本顺序为最初版、上一轮、本轮、本轮、上一轮、最初版。每服选索引 0、113、226、339 的 4 张不同难度谱面，共 8 张；挑战在该样本中只有 1 个输入，因此另对两服全部 24 张挑战谱面做了相同六轮顺序的串行对照，下表挑战行采用这组完整对照。每个版本每个输入先取两次均值，再统计配对加速比的中位数。CP 每服每目标为 1,000 次乱序预算查询。
- 全量本轮测试也按回放、激奏、搜索、活动依次串行执行。上一轮完整数据受并发与机器挂起影响，因此跨版本加速结论采用新跑的三版本串行对照；完整数据用于逐项结果核对与本轮全谱面绝对时间分布。
- 每项搜索新建任务并计入准备工作，没有沿用跨任务推荐结果缓存；任务内部复用属于本轮优化的一部分。同一进程的 JIT 会预热，因此这里不是每张谱面都重新启动浏览器或 Node 进程的测试。
- 机器：Apple M5、arm64、10 逻辑核，Node.js v24.19.0。墙钟、进程 CPU 与峰值 RSS 分开报告；没有测量电量或功耗。RSS 包含规则、谱面、JIT、堆和分配器保留的内存，不能当作单个缓存的内存占用。

最终代码的回归套件 174 项及额外固定分适配器 1 项通过。全卡差分对照上一轮：1,000 组受约束匹配完全一致；4,035 组成长配置分别比较等级 1 和上限；9,179 种成员—留影组合 × 5 技能等级 × 5 留影突破等级，共 229,475 项普通动态技能及激奏三任务编译配置一致，失败 0。激奏函数比较包含函数源码及配置，不表示每个五人队的全部实战轨迹已穷举。

## 复现与保留的边界

Node 必须使用 v24.19.0。原始数据和日志位于 `output/calculation-algorithms/round2/`；`baseline-*` 是上一轮完整输出的保留副本，`optimized-*` 是本轮串行运行。没有使用未完成或与回归测试争用 CPU 的中间计时目录作为最终结论。

```sh
node tools/verify_calculation_kernels.mjs \
  --baseline /private/tmp/otonote-algorithms-round1 \
  --datasets output/calculation-algorithms/current/datasets.json \
  --output output/calculation-algorithms/round2/kernel-differential.json

for phase in replay gekisou search events; do
  node tools/benchmark_calculation_algorithms.mjs \
    --datasets output/calculation-algorithms/current/datasets.json \
    --phase "$phase" \
    --output "output/calculation-algorithms/round2/optimized-$phase.jsonl" \
    --compare "output/calculation-algorithms/round2/baseline-$phase.jsonl" || break
done

node tools/summarize_calculation_benchmarks.mjs \
  --directory output/calculation-algorithms/round2 \
  --audit output/calculation-algorithms/round2/kernel-differential.json \
  --preserve-search \
  --output docs/designs/2026-10-10-calculation-algorithms-round2-benchmarks.json

node tools/summarize_calculation_controls.mjs \
  --directory output/calculation-algorithms/round2/control \
  --output docs/designs/2026-10-10-calculation-algorithms-round2-controls.json
```

三版本控制用同一基准工具的 `--root` 选择最初源码 `/private/tmp/otonote-algorithm-baseline`、上一轮源码 `/private/tmp/otonote-algorithms-round1`、本工作树，按前述六轮顺序对每个阶段串行执行，添加 `--stride 113`。控制输出文件名为 `{phase}-{0..5}-{original|round1|round2}.jsonl`，阶段还包括 `planner`。全部挑战独立复测使用 `--phase challenge`、不设 stride；汇总时使用 `--phases challenge` 和 `challenge-control` 目录。六轮均逐项核对其 24 个键与全量活动中挑战键集合一致。

源码冻结摘要为 `round1-source-sha256.json`、`round2-source-sha256.json`，原始最初基线为提交 `65788fe4211ac9c8e6fef08d4b5a8fc27874e429`；上一轮包含未提交变更，因此不能仅用该提交代替上一轮。

结果仍受以下边界约束：普通分数与挑战在给定预算内可能未完成；普通活动默认证明奖励元组，不证明同收益情况下的最高期望分；普通技能顺序按当前模型穷举，激奏含既有随机模拟假设；没有把实用推荐的结果称为已证明最优，也没有把全谱面固定成长基准称为所有玩家成长与所有五人队的穷举。本轮在计算耗时和 CPU 消耗上已实现主要路径的普遍收益；没有声称逐输入墙钟和每类内存峰值均已降低。所有改动和验证留在本地，未部署。
