# 演出情景与激奏机制：实现依据

规则与模型版本以共享计分包声明为准；本文区分静态依据与实机证据。

规则表、原生方法检查、代码测试与实机验证分别成立。以下计算模型不构成实机完整复现的承诺。

舞台的属性／任务覆盖、固定队伍多曲评估、轮换有效期及 Global 1.1.0 新卡技能复用边界，统一见[激奏舞台规则与配队接入](arena-stage.md)。本文的既有激奏支持范围不自动表示舞台或新版全卡池已接入。

## 公共输入

`performance-scenarios.mjs` 提供 `ideal`、`steady`、`practice`、`explicit` 与 `ap_timing` 情景。`steady` 与 `practice` 公开具体偏差、漏击概率与种子；它们没有经过个人水平校准。随机情景生成器只依赖谱面和情景，不依赖队伍；`ap_timing` 则结合队伍搜索固定操作，不经过随机样本生成器。

- `ournotes-performance-v1`：完整的明确判定、输入帧及技能顺序。判定不反推原始时机，不能用来衡量扩窗收益。
- `ournotes-performance-timing-v1`：完整的原始偏差、漏击标记和输入帧。先按规则表得到判定，再应用各队窗口与转换。
- 两者校验谱面哈希、全事件覆盖、输入顺序、帧率、显式时钟与版本。旧 AP 接口保持原来的默认情景。

`performance-scenario-calculator.mjs` 是推荐器的共用入口。固定玩家样本，分别遍历技能顺序及游戏随机；输出样本哈希、分布、段落指标和最好／最差样本回放。最低／最高分是本次抽样边界，不是理论极值。混合玩家波动后不沿用单个 LUCK 样本的标准误。

## 双帧率 AP 微操

`ap-timing-plan.mjs` 接入普通演出及挑战加成。初筛使用 10 种均衡技能顺序与正拍最佳顺序，精算对全部 120 种技能顺序先试算微操，避免先按正拍分截断顺序。在累计技能窗口内比较正拍、提前 20／25／30／40 ms、延后 20 ms 的策略，再删减不必要的操作。没有生效累计技能时沿用正拍最佳顺序，不为普通固定倍率的取整差异生成操作方案。仅调整手动单点、长条头与普通滑键，自动子音符保持原时刻，长条头不越过后续同条事件；不改变判定以追求非 AP 分数。候选政策和顺序不是穷举的逐键联合最优解。

微操候选按生效技能机制生成，不按卡片 ID 或歌曲白名单判断。普通固定倍率的开启、结束命令与音符都保留谱面时间，跨过技能边界的击键不会把窗口外音符纳入加成；但输入时机可以改变计分桶回算的 float32 历史，影响最终取整。`ap-window-range.test.mjs` 包含无累计技能的反例：同队、同顺序的全 PERFECT 输入从正拍 216,813 分增至 216,814 分，加成覆盖及连击不变。此类取整差异保留在原始回放和 AP 全窗口范围中，不用于生成推荐微操或提高配队排名。累计技能则用当帧音乐时间替换倍率，早晚按可以改变累计进度与倍率命令时间。以上是共享模型与既有原生函数样本的离线验证，不替代整场实机输入记录。

结果区统一检查最终方案是否包含调整键，以及复算得分是否高于同队、同顺序正拍在相同参考时钟下的较低分（`onTimeMinimumScore`）。新搜索与保存方案都经过这项收益比较；没有生效累计机制或没有收益时清除推荐偏移，恢复该顺序的正拍回放。界面显示正拍分数与技能顺序，不显示练习按钮、逐键微操表或零收益提示；有无微操都保留技能顺序、回放和最低／最高分入口。若用户主动选择范围端点回放，端点实际包含的输入调整仍可查看。

队伍与顺序快筛检查两档帧率和 0／1 ms 对齐。精算取六个领先候选检查统一 -5／0／+5 ms 操作偏移，再保留前三个并补入正拍方案，删减不必要的操作后继续检查 60 帧的 51 种、120 帧的 26 种参考时钟：保留零相位，并以 1/3 ms 分段中点覆盖均匀帧周期的整数毫秒时间戳排列。原始时机输入中的 `framePhaseMs` 指定参考时钟平移，不能与显式 `frames` 同时使用。这里的完整相位覆盖仅指均匀时钟模型，不代表音频同步客户端的所有时序。

排名依次比较已检查情景的较低分、最小 AP 判定余量与调整键数。统一偏移只加在需微操的键上，三个离散值不代表逐键独立误差的保分区间。每档单列正拍分、零相位微操分及有利对齐分；后者不进入主排名。界面不为这些分数生成概率、均值或实战保底解释，激奏暂不提供此入口。

保存方案绑定评分规则、谱面、综合力、技能和活动上下文。分享链接只保存顺序与逐键偏移等必要字段；读取后重建音符信息并重新评分，不信任保存的派生分数。上下文改变会重新搜索。回放同时输出实际输入时间与状态得分，播放和拖动共用记录，避免把计分桶的后续重算误当成只在击键时加分。歌曲页导入校验谱面身份和内容，改变难度后清除旧回放。

### 固定队伍的 AP 全窗口范围

回放中展开「同队 AP 的最低 / 最高分」并点击「计算分数范围」，固定当前推荐队伍与技能顺序，允许手动单点、长条头、滑键及导引线重合的手动起点，在各自 PERFECT 窗口内独立选择整数毫秒偏移。自动长条与轨迹事件保持正拍，同条起点与后续事件保持先后顺序。它与推荐方案的统一 ±5 ms 检查范围分别显示，不改变推荐排名。

`ap-window-range.mjs` 枚举可达输入帧，以动态规划合并相同的后续状态：已到达音符、累计次数、仍可能回退的计分桶及 float32 倍率历史。只有未来输入与技能命令都无法触及的计分桶才移出状态；相同状态保留最低、最高累计分及对应输入。逐键分数和桶回退复用共享计分核心。AP 下恢复与生命条件不随操作变化，由完整回放确定激活效果。改变 PERFECT 的转换／解除技能、另行改变逐键或结算得分的活动暂不支持此范围计算。

60／120 帧各自显示零对齐的最低／最高分，再单列完整参考对齐集合中的极值与条件。每个端点均用整曲回放复核 AP、总分和逐键输入；可选择端点回放、查看操作并导出到歌曲页。计算在工作线程中按需启动，关闭回放会停止；超过状态或转移预算时明确显示尚未得到极值，不用候选值替代。小谱面测试用独立输入帧笛卡尔积与完整回放核对动态规划的两个端点。

此处的精确范围只属于上述输入与均匀时钟模型，未重建触屏命中、长条按压和真实音频同步调度。不同端点使用不同输入，不是同一推荐操作的保分区间，也不证明跨队伍、跨技能顺序的全局最优。

| 激奏扩窗 4004 | 原有 float32 百分比窗口逻辑，原始操作情景测试激活前后变化 | 明确判定文件保留原判定，不凭空增加 JUST |
| 激奏转换 12006／13005 | 使用 Master 的实际目标判定与次数；仅成功转换消耗；13005 的正式目标包含 PERFECT 到 MISS | 普通转换先于激奏转换的混合排序仍需实机对照；不从技能文案推导排序 |
| COMBO 断连与保护 12004 | build 25 `GekisouController.RecalculateBonusDependentCounts` 0x55d66b8：0x55d6d20..0x55d6d54 使 3..6 增加任务连击并更新最大值；0x55d6e7c..0x55d6e88 使未保护的 1/2 重置当前值、保留最大值。0x55d6e08..0x55d6e60 消耗所有匹配保护项 | 保护只保留任务连击，失误不增加任务连击，也不修复普通连击和生命。COMBO 排名使用最大任务连击，当前任务连击另行输出 |
| LUCK／JUST／任务加成／结算 | 保留现有原生时间、抽奖、排名奖励与延迟确认实现；非 AP 判定进入 LUCK 基础点数和 PERFECT 数统计 | 对手是输入情景，不提供无依据的个人胜率 |

普通技能还支持按 PERFECT／JUST 每 N 次增加倍率（2001），分别读取累计次数上限和效果值上限；激活帧也读取当前帧判定，更新时撤销旧句柄再添加新句柄，结束后撤销当前值。理想 AP 与非 AP、普通与激奏共用生命周期，AP 不直接套用最大倍率。判定解除条件（1020）在执行状态检查，采用本帧最后一个匹配音符的谱面时间；激活帧及紧接的 ExecuteFrame 不检查解除。开局静态乐队条件、执行上限为一次的 BAD／MISS 到 GOOD 转换按成功转换消耗，次数耗尽后不随成员技能重新发动。尚未支持的执行重置条件仍明确拒绝。

累计倍率的替换命令使用更新帧的音乐时间，音符仍按谱面时间查询倍率。即使有效判定全部为 PERFECT，帧时钟的对齐方式和输入发生在哪一帧也可能改变计入技能的次数，以及跨过门槛的音符是否吃到新倍率。默认 AP 的最高／最低分固定理想输入，只遍历技能顺序，不覆盖这些时机变化。`scoring-content-compatibility.test.mjs` 用合成谱面验证同队、同综合力、同最优顺序下，全 PERFECT 的时钟平移和提前输入可以产生不同分数；移除累计技能后同一组情景保持同分。构造情景可以检验机制，不能据此认定某次实测采用了同样的输入时机，整场对账仍需真实输入记录。

Global 1.1.0 正常播放中的时钟链为 `MusicSyncTimeProvider.GetMusicSyncTimeMillSeconds` → `CriAtomExPlayback.GetTimeSyncedWithAudio`。音频库根据同步播放时间和计时器差值插值，限制在当前音频进度上界内，再将正微秒整数除以 1000 得到毫秒；暂停时不继续插值。`LivePlayingStateNodeBase.NormalizeTimeMs` 加上曲目偏移和谱面位置偏移并限制为非负值，随后原样传给触屏输入、谱面模拟位置和技能输入。累计加分在当帧记录替换时间，分数重算在命令与音符同刻时先应用命令。此路径不把音乐时间量化为固定的 `floor(帧号 × 1000 / 帧率)`；后者只是本站默认参考时钟。离线原生指令检查覆盖了音频插值、上界、暂停、毫秒取整及倍率命令的时间边界，音频设备、系统计时器和接口分派仍由夹具替代。音频同步计时器的接口语义另见 [CRIWARE 官方说明](https://game.criware.jp/manual/unity_plugin_en/latest/contents/atom4u_practice_0001_audio_synced_timer.html)。

这些新增普通机制检查了 1.1.0 原生方法：`SkillEffectUpdater` 的 Stay／ExecuteFrame／Executing、`SkillConditionNoteJudgementEqualChecker`、`NoteCumulativeScoreUpApplier` 和 `TargetJudgementConvertApplier`。`analysis/crypto/verify_current_ordinary_skills_native.py` 用显式私有路径和固定二进制摘要重放队长人数累计、上限、分量累计与判定除法的 ARM64 指令；合成样本保存在 `current-ordinary-native.json`。泛型集合、接口分派及属性匹配谓词由夹具替代，不能当作 Unity 调度或整场实机验收；当前整场模型仍保留参考兼容标记。

非 AP 的 `ordinaryReferenceScore` 当前表示保留该次有效判定、移除激奏得分倍率的参考值，结果以 `referenceKind` 明确标记。它不是另一次自由演出的独立模拟，也不是单卡贡献；换卡应比较整队结果。

COMBO 排名发送链已核对：`MultiLiveStatePlayingStateNode.OnTryConnectGekisouResult` 0x613c948 在 0x613cc8c..0x613ccb0 读取 `IReadOnlyGekisouRangeState` 槽 12（`get_MaxCombo`），经 0x613ccc8 保存并在 0x613cec8 送入结果的 Combo 字段，0x613cefc 发送；`CompareCombo` 0x60aaf6c 比较该结果字段。输出的 `sections.combo` 因而表示排名用最大值，`currentCombo` 表示段末当前值，`maxCombo` 明确保留最大值。

新增 `gekisou-combo-native.json` 保存 48 个原始 ARM64 指令块执行结果，覆盖 BAD／MISS 重置、GOOD 至 JUST 累加、多个有限保护同时消耗，以及有限保护与无限保护共存。执行范围仅为上述判定指令块，泛型 List 存取／删除由测试夹具替代，不能当作整段状态机或实机验收。保护撤销命令与音符同刻时先执行，因此区间结束为排他边界。

`3004` 生命伤害减轻按实际生命损失应用。同源刷新、跨来源叠加和生命条件得分联动由组合测试覆盖；具体卡片、等级和持续时间来自版本化规则，不在本文固定为某张卡的历史参数。

内容发布通过 `inspectPublishedSkillsCompatibility` 输出实际公开卡片各等级的诊断报告，不因计算器覆盖不全阻断资料发布。激奏条件与效果由独立程序组合，统一处理持续、释放、执行次数和重置；歌曲无关任务在解析技能细节前排除。相关缺失机制仅排除受影响配对并说明覆盖限制，真正的数据或程序错误仍明确结束为失败。组合执行接口见[共享计分包](../../packages/scoring/README.md)。

所有正式留影激奏技能的非 AP 入口均由自包含测试遍历。技能未触发不等于技能无用：生命条件、配对、区段类型、判定位置和剩余次数都保留在条件或回放数据中。仍未完成实机对照的组合排序列在前表，不隐藏为“已验证”。
