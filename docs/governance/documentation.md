# 文档维护规则

文档说明当前行为、操作方法和仍有价值的设计理由。改动过程由 Git 和 PR 保存，
不为每次任务创建设计、计划、交接、验收和完成报告。

## 入口与职责

[文档索引](../README.md) 是阅读入口；每个主题只有一份权威说明，其余位置链接过去。
索引中的 `current` 表示本文用于维护当前源码，不表示功能已经部署或通过实机验收。

| 位置 | 职责 | 创建条件 |
| --- | --- | --- |
| 根 README、CONTRIBUTING | 项目入口、贡献流程 | 保持简短，不追加任务进展 |
| `docs/governance/` | 文档、配置、公开范围等长期规则 | 规则确有独立职责时创建 |
| `docs/reference/` | 模块、数据、算法与能力边界 | 现有说明无法承接新的长期主题时创建 |
| `docs/runbooks/` | 开发、部署、巡检、故障处理和恢复 | 存在独立操作流程时创建 |
| `docs/decisions/` | 重要选择、约束、正确性依据 | 仅靠代码难以恢复设计理由时创建 |
| `docs/BACKLOG.md` | 尚未解决的问题或待验收关口 | 写清问题、下一步及完成条件；解决即删 |
| 模块旁 README | 该模块的使用和维护入口 | 靠近代码，不复制通用流程 |
| `docs/releases/`（按需） | 不兼容变化、必要迁移或重要用户变化 | 普通修改使用 Git／PR，不按日期凑记录 |

使用指南、技术概览、许可说明和部署入口保留稳定路径，供网站与外部链接访问。
新主题使用稳定的英文小写文件名；只有确实有时间边界的发布说明使用日期。
无需创建空目录或占位文档。

## 阅读与更新

| 工作 | 开始前 | 交付时 |
| --- | --- | --- |
| 开发 | 开发手册、对应模块说明与决策 | 更新受影响的契约、行为和用户说明 |
| 部署 | 部署入口、组件手册、配置边界 | 更新变化的步骤；实际环境与恢复材料私有保存 |
| 运维 | 当前组件手册和私有环境资料 | 把可复用结论写回手册，不追加现场流水账 |
| 故障修复 | 查现行规则和对应源码 | 修正失效说明；必要复现转为测试或简短故障条目 |
| 清理 | 索引、引用及文件用途 | 更新所有入口、链接和检查；未结项集中承接 |

文档与代码在同一变更中更新；若不需要文档改动，在 PR 说明原因即可。
小调整直接修订已有页面。临时推演留在任务对话或本地输出，不自动写入公开仓库。
新增公开文档必须登记到索引，说明唯一职责，避免双重权威。

代码、文档和实际运行不一致时，先核对对应提交与实际环境；不能把设计愿望写成现状。
配置结构以模板和解析契约为依据，线上值以实际受保护配置为准。验收分别说明离线测试、
资源回放、部署健康、浏览器与实机的覆盖范围；旧报告不证明现在的生产状态。

## 公开写作与私有材料

公开文档围绕本站需求、行为、限制和设计理由独立表述，不包含竞品网站的参考、
复刻或对照过程，不放其名称、链接、截图或比较数据。仍有用途的研究材料仅在仓库外保存。
必要的第三方代码署名、许可证、依赖来源和技术协议引用必须保留。

真实主机、个人绝对路径、账号、凭据、原始运行日志和配置备份留在仓库外。
公开命令使用明确占位符；合法通用容器路径与服务契约可以保留。
自动检查只能发现部分问题，提交前仍要审阅正文、图片和附件。
遵循[配置边界](configuration.md)和[公开源码范围](public-source.md)。

私有材料也不无限留档：只保留当前环境资料、仍处于恢复窗口内的备份、无法由 Git
或测试复现的必要证据。创建时记录保留用途和清理条件。文档治理不执行真实数据回收。

## 处置旧文档

删除前核对有效知识、未完成事项和必要恢复依据，将仍有用途的内容承接到对应说明、
待办或私有环境资料。已完成计划、重复报告和探索版本可以删除，不再复制到历史目录。
关键算法证明保留原理和适用范围，移除任务分支、机器跑分和过程日志。
被替代规则从当前操作手册中移除；必要兼容限制直接写入现行说明。

配置文件、示例、环境文件、部署脚本、服务定义、测试样例及程序读取的数据不属于文档
删除范围。附件须检查内容类型、直接和动态引用及实际用途；不确定则保留。JSON／YAML
不能因位于 `docs/` 或文件名含“历史”就删除。发现不宜公开的配置时单独报告，不擅自删改。
当前版本的删除不能清除已经公开的 Git 历史；历史清理和凭据轮换另行界定范围。

## 提交前检查

```sh
python3 -m tools.docs_status
python3 -m unittest tests.test_docs_status -q
sh scripts/check-repository.sh --scope staged
git diff --check
```

文档检查覆盖索引、路径、相对链接和部分公开内容规则，并通过既有 CI 文档测试执行。
新增检查规则不能靠放宽配置／脱敏边界来通过。纯文档整理不触发部署或重写 Git 历史。
