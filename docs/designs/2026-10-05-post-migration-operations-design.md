# 迁移后的发布、运维入口与内容编译

用户已授权直接发布、清理服务器上被替代的旧管线，保留并改造管理面板，然后优化有内容变化时的完整编译。

## 交付边界

1. 使用 main 成功 CI 的同一份验证候选发布前端，核对两服两语言预渲染与真实浏览器。一起部署新功能需要的网关模块；不使用真实账号制造验收数据。
2. Actions 负责游戏探测、生产与 R2 晋级；现有服务器只承担网页、按需内容材料化、预渲染及独立 API。将前端发布器移出旧更新器目录，使剩余旧资源树可以退役。
3. 删除前按活动容器挂载、systemd、Nginx 和私有部署配置逐项核对。保留新管线当前和上一版、管理面板任务历史、玩家观测/身份数据、独立登录与排名服务。审计记录只含路径和摘要，不含密钥。

## 管理面板

资源页改为内容发布页，分别显示 Global、JP 的 Actions 生产、R2 内容和服务器交付关系，以及实际已经材料化/渲染的版本。手动生产通过仓库的 Run workflow 入口选择 main、region、promote；shadow 的用途明确说明。

服务器采样只证明站点交付状态，不冒充 Actions 实时运行状态。面板无需增加 GitHub 写入凭据，GitHub 保持现有身份验证和审计。迁移 profile 不再具备旧本机生产能力，旧任务仅作历史；node API 和队列执行器同样阻止旧任务，不能只隐藏按钮。

## 有变化时的编译

已观测的生产阶段 Global 38m21s、JP 49m41s；此前无变化快速探测并不覆盖此问题。真实图片重放验证缓存复用、编码并发与两语言重复工作三种可能。

现有图片派生缓存位于临时 runner 没有 checkpoint 的目录。将两服转换缓存置于已有状态白名单内的 workspace/cache/image-conversions，保留压缩派生文件及其校验回执，不复制原始 PNG。缓存键绑定输入 SHA、转换参数及编码器版本，命中时校验输出摘要。只对新增/变化图片重新编码，完整 JSON 投影依然依据本次内容构建。

冷缓存/大量新图使用有限并发编码，输出顺序和内容保持确定性。异常立即阻止候选发布；相同摘要并发写缓存必须校验内容一致。实测额外缓存体积和恢复成本，不能只展示编码微基准就承诺整条更新耗时。

## 验收

- 固定回执的 frontend 发布、两服实际代码身份、浏览器工具初始化与网关能力一致。
- 旧管线没有活动入口/任务，独立发布器仍可幂等发布；新定时器及独立 API 健康。
- 管理面板显示两服、标注采样时效，旧任务 API 被拒绝，历史可查。
- 真图冷/热/单图变化重放，增量与同输入全冷产物 SHA 一致；损坏缓存、编码参数变化、并发冲突均可检出。
- CI 通过后进入 main，真实 Actions 运行记录阶段耗时；首次新缓存建设与后续增量收益分开报告。
