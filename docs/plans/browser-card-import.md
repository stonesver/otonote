# 浏览器截图导入卡库

用户已选择浏览器方案，并确认多张截图中的同一卡牌养成需要合并。沿用已验收原型的 ORB 候选筛选、几何验证、局部数字 OCR 和星角/花瓣计数。

在“我的卡库”和配队页的共用卡库组件添加截图导入。点击后按需加载识别资源，自动判断截图类型，不确定时提供原生下拉框更正，然后运行 Worker；图像只存在于设备内存。识别后按卡牌 ID 合并为可编辑的草稿，卡面低置信度默认不选，相同字段不一致必须手动解决。保留逐图裁片供核对。

保存前明确展示新增/更新、当前值和待应用值。已有卡仅覆盖观察或手工填写的字段；新卡必须补齐等级和阶数；按用户明确指定，新角色卡的两种技能默认 1 级，并提供用户主动执行的“两种技能一键满级”操作。已有卡未指定技能时保留原值。角色特训映射 `awake`，觉醒星数映射 `rank`；留影花瓣映射 `rank`。所有最终值由现有规则验证，写入走现有 commit/saveInventory，并复用撤销；保留账号乐器、角色评级及其他卡。

前端代码和第三方引擎随不可变代码包交付，运行库依赖由 npm 锁文件固定，不依赖运行时 CDN。卡面特征是内容产物，绑定区服版本与 sourceReleaseId，由独立构建器生成，并通过内容发布器校验、封装到不可变内容快照。缺少对应索引时明确提示不可用，禁止跨版本偷偷回退。打开导入面板后后台准备大资源，显示阶段进度；固定版本使用 HTTP 缓存和 OCR 模型本地缓存。

验证覆盖：字段映射、缺失值保留、新卡缺字段拒绝、冲突、区服/内容绑定、保存/撤销、取消后重试、资源错误重试；代码构建与内容封装测试；真实浏览器的上传—识别—校对—保存—撤销。原型网格限制仍公开说明，任意裁剪和手机准确率不伪称已验收。配置、原始截图、游戏媒体及索引均不提交。上线发布不属于本次自动执行范围。
