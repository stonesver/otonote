# 工具和卡库首次加载

## 诊断

在已发布的 `d7d0fdd6475ee7a5c58c8d5c` 上清空浏览器 HTTP 缓存，分别进入配队、估分和活动收益，工具可用后立即打开共享弹窗。记录 Resource Timing、CDP 请求发起者和主线程长任务；冷缓存不代表 CDN、DNS 或连接池全部冷启动。

本轮单次线上基线：工具可用分别 4.42 / 5.66 / 4.44 秒，弹窗可用 2.82 / 2.81 / 2.81 秒。此前的 12 秒是另一轮观测，不能作为每位用户固定耗时。本轮没有记录到 50 ms 以上的主线程长任务。

按请求瀑布确定的优先级：

1. 工具 JSON 到 DOMContentLoaded 才开始下载。配队页从 1.962 秒开始，到 2.859 秒完成。
2. 原 HTML 只预加载交互入口。共享依赖在入口解析后逐层发现，部分必要代码到数据完成后才发起，造成数轮网络等待。
3. 工具的 JSON 已包含 `growthIcons` 和 `filterVisualOptions`，弹窗仍导入展示模块，再串行读取 manifest 和 catalog。卡片数据复用并未覆盖展示数据。

另检查了解析 / 渲染阻塞和图片竞争。当前证据更支持请求发现太晚与串行加载；没有据此改写计算逻辑或进一步删减所需数据。

## 修改

- 预渲染 HTML 在 head 预加载工具 JSON，使用与后续读取一致的 CORS / credentials 设置；后续仍校验原有 SHA-256。
- 编译时从 esbuild 元数据提取交互脚本的完整静态依赖。HTML 一次预加载本页需要的代码，去重并保留原有执行顺序；JSON 准备完成才初始化工具。
- 用户悬停、聚焦或点击卡库入口时一次预加载弹窗静态代码。动态内容模块、截图识别引擎和 worker 不纳入静态闭包；预加载本身不执行代码。
- 已加载工具的弹窗直接复用完整展示数据。兼容缺少展示数据的旧上下文，也保留普通页面独立读取卡库的路径。

选择按页面及操作意图预加载，而非全站下载所有功能，以减少请求轮次，同时控制无关下载。

## 本地验证

先补回归检查，修改前因缺少数据预加载、静态闭包和展示数据复用失败；修改后加载、导航、取消、计算进度与收益 / 冲榜 UI 共 41 项测试通过。新增静态依赖回归加入公开 CI。

同一份本地内容、旧线上代码与新编译代码、浏览器 HTTP 冷缓存、固定 200 ms 延迟及 10 MB/s 带宽下：

| 页面 | 工具可用：旧 → 新 | 弹窗可用：旧 → 新 |
| --- | --- | --- |
| 配队 | 2.14 → 1.30 秒 | 1.82 → 0.81 秒 |
| 估分 | 2.23 → 1.29 秒 | 1.81 → 0.80 秒 |
| 活动收益 | 2.18 → 1.26 秒 | 1.81 → 0.30 秒 |

工具数据提前约 0.63 秒发起，浏览器和服务器记录均只有一次 payload 下载；三种工具内弹窗不再发起内容 JSON 请求。没有计算器上下文的工具目录弹窗从 2.31 → 1.80 秒，仍正常读取所需卡库数据。

这些是固定测试条件下的实测，不是所有用户耗时承诺。线上发布后需另测冷缓存与图标、卡库交互、计算进度、完成及停止状态。

## 线上复测发现的启动阻塞

第一阶段发布为 `7c16d1909491f4350f1a19bc` 后，确认 payload 只下载一次，工具内弹窗不再请求内容 JSON；工具可用耗时却出现较大波动，不能据此宣布线上优化完成。

新的独立浏览器中，一轮估分的必需代码与数据约 3.7 秒已完成，Cloudflare 统计脚本到 9.9 秒才结束，DOMContentLoaded 随之延迟。原 bootstrap 在这个事件才开始准备工具，形成额外阻塞。

跟进修改：在文档进入 `interactive`（完整结构已解析）时准备工具，不等待无关的 deferred 统计脚本。数据 SHA-256、全部 JSON 齐备及必要模块按顺序初始化的门槛保持原有检查；普通页面的生命周期通知继续原有安排。

新增回归检查验证解析之前不会启动、进入 interactive 后立即启动、后续事件不会重复初始化。真实浏览器人为挂起 deferred 统计脚本：旧版一直保持 pending，新版在统计请求仍未返回、DOMContentLoaded 尚未触发时已显示可用工具。
