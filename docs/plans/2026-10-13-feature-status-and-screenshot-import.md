## 实现约定

`content-r2.yml` 对 Global/JP 均传入 `--card-recognition`，功能门禁传入 `--require-recognition`。生产镜像增加现有锁定的 OpenCV/NumPy/Pillow 依赖，拉取后先离线 import 预检，旧镜像在恢复大状态前失败。

索引从封存候选派生，缓存键包含候选、算法和生成器源码；不修改封存候选。JP 将耗时索引准备放在最终源版本重查之前。元数据和特征摘要纳入新的内容身份。发布器及功能门禁核对卡牌种类、卡面归属，以及每个预期卡面是已索引还是明确缺失；缺失以 partial 对用户可见。旧/跨服/损坏/未知算法索引不能作为当前索引使用。

“索引可用”表示当前内容的索引契约与覆盖符合要求；设备引擎是否可运行在打开工具时单独检查。普通浏览不下载引擎。页面展示未知与陈旧状态，不混用新旧快照，也不把未知评分规则显示为可用。

## 上线顺序与回退

1. 审阅本批代码，先只合并镜像依赖提交（Dockerfile 与镜像构建工作流），用现有仅允许默认分支的镜像工作流构建并取得不可变 digest，再切换生产镜像配置；之后才合并功能及必需索引门禁提交。不能将两个提交一起合并后仍使用旧镜像运行定时任务。
2. 按现有候选/功能门禁/上传回读/checkpoint/晋级流程产生双服含索引的新内容，复用现有私有状态。核对有无正在运行/已自动触发的任务，同一区服只跟踪一轮必要的新产物发布；不重复既有空 runner 与无变化验收，不运行 finish_cloud_acceptance.py。
3. 发布本批前端并预渲染，核对双服主指针、交叉引用、目录与截图索引摘要、新卡覆盖、用户可见状态，再抽查正式导入流程。
4. 失败不晋级；保留旧内容/网页和镜像 digest。必要时按现有受审回退流程恢复指针/代码，不删除新不可变对象，不清空用户库存。旧内容本来缺索引，回退后明确显示未提供，不能伪装截图可用。

本批尚未执行镜像构建/推送、生产配置切换、内容晋级或前端上线。专用 GitHub Token、外部触发器、Analytics 凭据继续暂缓；不重复清理磁盘、不扩大告警渠道。G 尚保留上线验收、新机制实战、独立截图测试集与真实设备性能证据。
