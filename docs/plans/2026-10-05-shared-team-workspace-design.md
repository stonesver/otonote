# 卡库与队伍共用浮窗

状态：本地实现与候选验证完成，待用户审阅。未推送、未上线。交付与验收记录见[完成报告](2026-10-05-shared-team-workspace-completion-report.md)。

## 1. 玩家要完成什么

在任意工具页打开同一个浮窗，查看和维护卡库、管理多套有名字的队伍，并把选中的队伍用于当前工具。工具算出的队伍也能存回这里，换工具时不用再选一遍十张卡。

卡库记录实际持有和实际养成。队伍记录五组成员与留影的配对、队长及使用的养成场景。歌曲、活动与收益条件属于当前工具。这三类数据明确分开，界面上提供连续的操作路径。

## 2. 方案取舍

| 方案 | 使用感受 | 取舍 |
| --- | --- | --- |
| 固定入口＋侧边浮窗（推荐） | 桌面可一边看当前工具，一边选卡和队伍；手机为全屏面板 | 用同一套状态与组件服务各页，能保留页面上下文 |
| 居中模态窗口 | 结构简单，窄屏容易适配 | 经常挡住待比较的结果，频繁开关不方便 |
| 任意拖动的小窗口 | 可自行摆放 | 手机体验差，遮挡与焦点管理更复杂，拖动本身不能解决数据割裂 |

选择第一种。默认不提供拖动、缩放和多个并存窗口。

## 3. 入口与布局

所有工具页有一致的“卡库与队伍”入口，可显示当前队名和未保存标记。入口不覆盖原有提交、取消或手机底部操作区域。

桌面打开右侧面板，在空间足够时与工具内容并排；窄屏使用覆盖式面板；手机使用全屏面板。打开后保持所在工具，不跳往配队页。关闭面板保留筛选、滚动位置和未保存编辑，切换区服则使用对应区服的数据。

面板有两个主要页签：

- **我的队伍**：置顶显示“当前工具使用”，下方是可搜索的已存队伍。每项显示名字、五组卡、队长、实际／培养计划／参考标记，以及当前工具是否可用。
- **卡库**：成员／留影切换、搜索和筛选、已持有与未记录、实际养成编辑、导入／导出。账号的乐器、角色评级和 TGW 放在折叠的“账号养成”中。

队伍编辑直接在面板内完成，支持换卡、配对和队长调整；培养目标仍与实际养成分开。保留独立“我的养成”页作为较大屏幕的完整管理入口，但它与浮窗使用同一份数据。

## 4. 当前队伍与已存队伍

按账号区服保存一个最近使用的队伍草稿，让玩家进入另一个支持编队的工具时能直接继续使用。每个工具载入后拥有自己的工作副本；已打开的其他页面不会被强制换队。

进入工具的优先级：明确分享链接或从结果跳转携带的队伍，其次为最近使用的队伍，最后为工具的空状态或参考场景。URL 中明确指定的歌曲、难度和场景继续有效。

点击“用于当前工具”只切换队伍及其实际／计划养成语义，保留该页已选的歌曲、难度、活动和收益设置；不会把某个活动的倍率或激奏名次套进其他模式。已保存的发挥条件可作为单独的“同时带入发挥设置”选项，默认保留当前页设置；不兼容的模式条件不载入。

切换前检查当前页草稿有无未保存修改。需要时提供“保存后切换／放弃修改并切换／取消”，不静默覆盖。工具正在计算时，应用另一队必须停止或作废原请求，旧结果不能覆盖新队伍。

编辑或计算产生的新队伍，必须主动保存才修改已存队伍。结果上的按钮统一为“存为队伍”；先填写名称，预填可修改的建议名。默认保存为新队伍；另有明确的“更新已有队伍”操作。重名提示但不据名字自动覆盖，记录使用稳定 ID。支持重命名、复制和删除，删除可撤销。

卡库变化会通知当前页和其他已打开的工具：实际队伍重新读取实际养成、旧计算失效；培养计划保留目标并刷新实际差额。不会把培养目标写回卡库。离线或跨页面恢复不丢失“未知养成／未知持有／参考值”的来源。

## 5. 活动限制和兼容性

浮窗读取当前工具声明的规则，不自行猜测活动规则。

| 类型 | 界面行为 | 计算行为 |
| --- | --- | --- |
| 明确禁止的卡、角色、乐队或属性 | 可见但灰显，显示具体原因 | 换卡和应用队伍时拦截；Worker输入处再次校验 |
| 当前活动限定歌曲／难度 | 歌曲选择器显示同一套可用条件；不兼容时提示重新选歌 | 不沿用上一个活动的非法歌曲 |
| 活动额外加成 | 正常可选，单独标注加成 | 仍由现有活动规则在正确环节应用，不等同于禁用条件 |
| 玩家主动设置的搜索偏好 | 在搜索范围中体现，可调整 | 不永久改写持有状态，也不冒充游戏硬限制 |
| 工具不支持某类场景 | 队伍可以查看和编辑，应用按钮解释原因 | 不把不支持的计划或模式悄悄降级成实际队伍 |

已存队伍包含被禁用的卡时，保留完整队伍，显示冲突位置。提供“复制并调整”，不自动移除或替换原卡。活动或模式变化后重新检查正在使用的队伍，在修正前不继续使用旧结果。

参考和试用队伍仍可保存。要求实际持有的计算入口不得把它们当作真实卡库；支持理论比较的工具则明确显示假设。

## 6. 各页接入

| 页面 | 处理方式 |
| --- | --- |
| 卡组配队（普通／激奏） | 当前队伍摘要＋打开浮窗；撤下重复卡库编辑和预设管理区；保留选歌、表现、目标、搜索约束、多方向结果及曲池比较；每个结果可命名保存 |
| 歌曲计算 | 使用当前队伍；撤下独立预设下拉；页面保留歌曲、回放与模式条件；可保存当前编成 |
| 活动收益／挑战配队 | 使用同一队伍与卡库；页面负责活动、歌曲、资源和收益条件；挑战候选及收益方案都能保存到浮窗 |
| 队伍 AP 达档 | 使用同一队伍，撤下重复选卡和预设入口；保留档位、曲池与模式设置 |
| 歌曲排行榜 | 能打开管理面板；固定基准榜不受个人队伍影响，明确说明。提供携带选中队伍与歌曲进入个人计算的入口 |
| 账号导出、资源、Live2D等非编队工具 | 可以打开同一浮窗管理资料；没有队伍计算能力时不显示“用于本页”，不添加虚假的个人计分功能 |
| optimizer／gekisou-lab旧地址 | 沿用现有重定向，避免再维护另一套浮窗 |

不把所有工具的参数都搬入浮窗。页面应该清楚回答“这次算什么”，浮窗负责“用哪些卡和哪套队伍”。

## 7. 数据与接入边界

现有源码核查：

- `personal-growth-store.mjs` 已按区服保存长期卡库和账号养成，可作为唯一实际养成来源。
- `preset-portfolio-ui.mjs` 自己读写带内容版本的预设存储；`tool-presets.mjs`、`ap-grade-ui.mjs` 又分别读取。需要合并成独立的队伍存储层。
- `event-team-view.mjs` 和 `challenge-optimizer-ui.mjs` 有各自的应用队伍逻辑；应通过共用接口连接浮窗，而不是共享页面DOM或复制十组控件。
- `song-ranking/index.astro` 明确使用固定基准，不能因为有共用浮窗就暗改为个人排行。

实施拆为四个职责：

1. **资料与队伍存储**：按区服保存卡库、命名队伍和最近草稿；负责校验、迁移、导入导出、修订版本与变化通知。页面不得另写平行存储。
2. **工具上下文适配**：声明本页是否使用队伍、允许的卡与歌曲、支持的养成场景，以及如何读取／应用队伍、作废结果。应用和保存走同一接口。
3. **兼容性检查**：返回整队及各槽位的可用状态与原因，复用既有规则数据；同一检查用于展示、应用和发起计算前。
4. **浮窗组件**：统一编辑、命名和选择交互；数据按需加载，不在所有非编队工具页启动时加载整套谱面和计算器。

延续浏览器本地计算，不新增个人数据后台。相同浏览器、相同网站来源内共享；本地预览与线上、不同浏览器之间通过备份导入导出，不声称自动互通。

## 8. 兼容、导入与异常

- 兼容现有 `otonote-personal-growth` 版本1备份。它只携带卡库和账号养成，不包含命名队伍；导入时不清空已有队伍。
- 队伍库采用独立长期身份，内容版本作为校验依据，不再成为让整库消失的存储键。旧预设从相应区服迁移，保留原始备份；多个旧内容版本冲突时提供可理解的来源选择，不能随意取最新一份覆盖。
- 导入先展示区服、内容匹配和增减摘要，再应用；失败不部分写入，支持撤销上一次导入。错误区服不得混入当前资料。
- 遇到新卡或内容缺失，提示刷新匹配内容或保留待处理文件；不静默丢弃不认识的卡，不默认补满养成。
- 同页事件和跨标签页通知均带数据修订号。两个窗口同时编辑同一队伍时检测冲突，提供另存副本，不依赖最后一次写入覆盖。
- 存储配额不足、备份损坏或浏览器禁用存储时保留当前输入，提供导出，不谎报保存成功。
- 未选择账号区服时可以浏览参考数据；首次导入或持久保存时在浮窗就近完成区服选择，避免按钮报错后让玩家到页头寻找设置。

## 9. 界面与文案

常用按钮只保留“用于当前工具”“存为队伍”“重命名”“复制”“删除”。养成差异用“还需培养2张卡”“这张卡未记录等级”等具体说明，不用空泛的推荐话术。

禁用原因就近展示，例如“本期只允许某乐队成员”“这套队伍含1张未持有卡”；加成提示则写“本期有额外综合力加成”。空卡库提供导入、手动录入和查看参考队伍入口。

键盘可以打开、切页签、应用、命名和关闭；覆盖式面板管理焦点并支持Escape，关闭后返回原入口。保存成功使用状态提示，不替换按钮成错误长句。中英文覆盖新浮窗和相关主流程；保留卡名等内容实体。

## 10. 验收和交付

用户本轮提供的真实备份已在匹配内容版本下通过现有导入、内存保存和再次读取检查，养成完整。旧仓库规则样例不能识别部分新卡，因此实际验收必须使用匹配内容快照。真实备份不复制进源码或测试夹具；自动测试使用独立合成资料。

必须走通以下流程：

1. 在歌曲计算页打开浮窗并导入备份，核对卡库、乐器、角色评级、TGW；切到配队页无需再导入。
2. 创建两套有不同配对和队长的命名队伍；在三个个人计算工具中选择，队伍一致且页面歌曲／活动不被意外覆盖。
3. 普通、激奏、挑战和收益结果都能命名保存；返回其他工具即可看到和应用；重名不覆盖已有队伍。
4. 修改卡库实际养成后，各页结果正确失效；培养计划保留目标、更新差额，不反写实际资料。
5. 活动限定卡牌／歌曲时显示禁用原因，在应用与计算入口均能拦住非法队伍；纯加成不禁用普通卡。
6. 未保存编辑、计算中换队、跨标签冲突、导入失败、撤销和区服切换均保留正确数据。
7. 内容版本变化、旧预设迁移、备份往返不丢队名、配对、目标或参考标记。
8. 390像素手机与桌面检查面板、选卡、命名、禁用解释和返回结果；不得再出现旧样式遮挡按钮的问题。
9. 清理重复入口后检查各页首次载入、分享链接、旧书签及既有计分回归。

实施顺序：共享存储和迁移 → 浮窗与配队／单曲贯通 → 活动／挑战／AP工具接入 → 其他工具入口与重复界面清理 → 数据、浏览器验收及正式候选。每一阶段交付可用路径，不另起一套无法串联的演示组件。

完成后仍提供本地审阅、报告和候选回执，不推送或部署，直至另行授权。
