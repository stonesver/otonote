# JP 客户端自动升级

官方 Version RPC 的推荐版本变化使轻量门禁转入完整恢复。可信旧客户端提供签名和
metadata 信任基线，不将某个历史版本号作为永远有效的最新客户端。

## 信任与输入

新 XAPK 必须符合官方推荐版本及递增 versionCode，每个分包通过官方签名、包身份和
集合校验。第三方包站仅提供传输，不替代官方版本与签名依据。输入材料与绑定收据保存在
私有状态，不提交 APK、真实映射或解码材料。

升级要求旧材料在新 metadata 中唯一重定位，至少三个不同加密 bundle 验证成功，
并通过新客户端 Version RPC。新 seed 回执及可信旧 metadata 随 checkpoint 保存，
生产、轻量恢复与后续无变化判断使用同一绑定。旧回执只按明确兼容规则复用，否则完整验证。

认证材料变化、metadata／Unity 结构不支持、HTTP 拒绝、维护或任何校验失败时停止，
保留旧 seed 和公开内容。取得新包不等于内容生产完成。代理仅作用于允许的 Version
端点，见[JP 出口手册](../runbooks/jp-egress.md)。

## 交付检查

核对运行镜像和安装程序包含对应实现与依赖；不能因仓库已修改就认为线上获得能力。
先验证签名、重定位、旧回执兼容、完整状态恢复与无变化分支的定向回归，再完成真实
新客户端 RPC、云端 shadow、明确授权下的 promote 和双服页面验收。
本地合成输入或单个新包解密通过不能代替这些关口。
