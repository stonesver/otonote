# OtoNote 工具工作台 V3：A 与 B 融合

2026-10-09。用户接受工作台方向和 A／B 的结合，要求继续改善视觉、排版与内部交互。本稿记录新的可体验原型；功能边界沿用 V2，歌曲排行榜仍独立。

后续：用户认可大布局后，选择面板、已选队伍与控件已在 [V4 设计稿](2026-10-09-tools-selection-panels-v4.md) 重做。本稿保留大布局决定，选择交互以 V4 为准。

## 本轮设计问题

**同一工作台能否在调整条件时同时核对结果，在比较方案时让结果获得足够宽度？**

上一轮 A／B／C 的比较已收敛。本轮只有一个工作台，包含展开条件、收起条件、手机条件抽屉三种状态。旧 `variant=A/B/C` 原型链接会进入 V3；不再循环三套布局。

## 结构

```text
站点导航 │ 标题与任务切换
         │ 当前队伍摘要                               编辑 ↗
         │ ┌ 计算条件 ─ 收起 ┐  状态             计算按钮
         │ │ 推荐目标       │  条件摘要
         │ │ 卡片与养成     │  ┌ 候选名称      主指标 ─┐
         │ │ 歌曲与演出     │  │ 候选切换             │
         │ │ 编成限制       │  │ 五组成员／留影配对   │
         │ └───────────────┘  │ 结果条件、应用、明细 │
         │                    └──────────────────────┘
```

收起时左栏成为 64px 的摘要栏，显示任务目标、来源及歌曲。重新展开不重新计算；条件值、候选和结果保留。结果排序始终留在结果面板。

手机隐藏常驻条件栏，展示摘要与“调整条件”按钮，打开全屏抽屉。抽屉内部滚动，计算按钮固定在底部；关闭后继续看同一结果。

## 视觉重新组织

| 部分 | V3 的具体变化 |
| --- | --- |
| 工作区 | 浅灰紫背景；结果使用白底，移除整块浅蓝底 |
| 操作 | 紫色用于计算、应用和选中项；辅助动作缩小视觉权重 |
| 标题 | 页面标题、任务切换、结果标题、输入分组形成不同层级 |
| 条件栏 | 桌面 292px；分组边线划分，避免每组再套独立外框；内容可滚动 |
| 当前队伍 | 一条紧凑摘要；明确它与推荐候选的关系 |
| 推荐结果 | 候选名称与主指标并排，缩短结果头部；下面直接展示配对 |
| 配对卡片 | 成员和留影放在一个连续单元，属性色只用于识别；队长单独标记 |
| 多曲结果 | 曲名／谱面、时长、档位、估分、单曲入口对齐成列；排序控件放在表格上方 |
| 手机编辑 | 五个位置用两列紧凑摘要，选卡列表能更早出现在首屏；底部确认固定 |
| 原型标记 | 缩为右下角状态入口，不再用大型布局切换条遮挡结果 |

字号与圆角在原型中可继续调整。当前卡面没有真实图片，使用名称和属性色验证信息密度；不能把名称占位当成正式卡牌视觉方案。

## 保留的功能归属

- 配队的推荐目标与培养／试用是不同维度，可组合。
- 卡库管理与手动编成编辑分开。编辑面板只修改草稿，确认后应用。
- 估分与选曲只含单曲和多曲两个页签，使用固定队伍。
- 活动收益分为已知加成速算和卡库完整规划。
- 歌曲排行榜仍是独立入口，采用统一基准。
- 推荐候选不自动覆盖当前队伍；参考／培养／试用标记继续保留。

## 本轮实际验证

浏览器视口：桌面 1280×800，手机 390×844。后续走查使用独立标签页，避免改变用户正在体验的原型状态。

| 任务 | 实际观察 |
| --- | --- |
| 展开条件 → 推荐 | 迷星叫 EXPERT 的样例推荐完成，五组配对及队长显示完整 |
| 收起条件 | 结果宽度从 714px 增至 942px；分数、候选、五组配对不变 |
| 选曲排序 | 收起条件后改为短歌优先，壹雫空排第一，结果保持已生成状态 |
| 手机条件抽屉 | 宽 390px；计算按钮底部为 828px，在 844px 高视口内可见 |
| 修改等级上限 | 从不限改 Lv.25 后，旧六曲结果保留为快照；单曲入口禁用 |
| 重新计算 | Lv.25 范围下只展示迷星叫、影色舞、春日影三首样例 |
| 手机配对编辑 | 单个位置摘要高度从约 175px 压缩到 100px，选卡列表更早可见 |
| 编辑并应用 | 位置 2 换“心爱的企鹅们”，原位置交换留影，位置 2 设队长，应用后当前队伍更新 |
| 编辑后选曲 | 固定编辑后的当前队伍，选曲流程完成；390px 页面无横向溢出 |

修正了两项走查发现的问题：旧选曲结果过期后仍可点单曲入口；编辑卡片过高把选卡列表推到首屏之外。编辑卡牌类型、选卡、队长更新时也保留编辑区滚动位置与对应按钮焦点。

脚本语法检查与 `git diff --check` 通过。没有重跑正式计算测试或完整站点构建，因为本轮只修改独立原型与设计稿。

## 验证边界

- 分数、曲长、编成、奖励都是样例，没有接真实引擎。
- 培养、试用、约束等控制只验证状态与交互，不能证明最优队伍或游戏合法编成。
- 无持久化、账号写入、API、部署或正式工具重构。
- 没有真实手机软键盘、触屏和辅助技术验收。
- 色彩对比、真实卡面、长列表过滤与生产组件状态仍需在正式实现时完善。
