# 共用卡库与队伍浮窗完成报告

对应[已确认设计](2026-10-05-shared-team-workspace-design.md)。开发分支为 `codex/shared-team-workspace`，按功能拆分提交；并行开发使用独立 worktree，审查后集成。仅供本地审阅，未推送、未上线。

## 已完成的使用流程

所有工具页提供“卡库与队伍”入口。宽屏为侧边面板，手机为全屏面板。卡库记录实际持有和养成，队伍保存五组配对、队长与培养场景，工具页保留歌曲、活动和计算条件。

| 玩家操作 | 实现结果 |
| --- | --- |
| 查看或维护卡库 | 成员／留影、筛选搜索、逐卡实际养成、账号养成、备份导入预览与导出；导入覆盖可撤销 |
| 管理多套配对 | 自定义名称、新建、复制、重命名、更新、删除撤销、名称搜索；队伍按稳定 ID 保存，重名不会自动覆盖 |
| 在不同工具继续使用 | 应用已存队伍或恢复最近使用的队伍；保留当前页歌曲、难度和活动，取消旧计算；明确分享链接中的编成优先 |
| 保存计算结果 | 配队、挑战推荐及收益方案统一通过“存为队伍”进入命名；保存不会修改实际卡库 |
| 比较未养成的卡 | 当前养成、培养后使用、满养成参考、保留手选养成、试用未持有卡；培养目标与真实记录分开 |
| 进入受限制的活动 | 按工具声明检查卡、角色、乐队、属性、歌曲与难度；显示不可用原因，保留原队伍并允许复制调整；额外加成不当作禁用 |
| 使用非编队工具 | 仍可管理队伍和卡库，但不出现无效的“用于当前工具”按钮；固定基准排行榜不受个人编成影响 |

已保存队伍与卡库按账号区服隔离；兼容旧预设的显式导入，原记录保留。队伍备份默认合并。切区服或覆盖工作副本前处理未保存修改，跨窗口冲突保留输入，并提供另存副本。网页存储不可用、备份无效或版本不兼容时显示错误，不静默清空记录。

## 浏览器验收

使用用户提供的真实卡库备份，在本机预览中导入 50 张成员卡和 63 张留影。私人 JSON 没有提交到 Git，也没有上传到线上。

- 新建“日常稳分队”，选满五组配对；另存“日常队·培养计划”，将一张成员卡的演出技能改为 3 级。
- 从配队切到歌曲计算，再到 AP 工具，队伍与配对保持一致，计划中的技能等级正确带入；卡库仍保留原来的技能 1 级。
- 挑战演出只显示本期三首挑战歌曲。选定 EASY 谱面后完成候选计算，点击候选的“存为队伍”，命名保存成功。修复后将最高分候选保存再应用，在相同条件下重新计算仍为 621,675 分，综合力 176,711，配对、队长与各卡等级保持一致。
- 资源页可打开相同卡库和队伍列表；英文入口与浮窗主要操作文案已检查。
- 检查 390 像素手机和 1600 像素宽屏布局，以及未保存修改的取消／放弃、删除撤销、卡库未保存时的切区服提示。

截图保存在本地忽略目录 `output/shared-team-review/`，不随源码提交。真实活动数据目前验证了歌曲限制；更广泛的卡、乐队、属性禁用使用合成测试验证，不声称已在游戏内观察到这些限制。

## 自动化与候选验证

全量 Node 测试 982 项通过。类型检查覆盖 672 个文件，0 错误、0 警告、24 项提示。候选构建器相关 Python 测试 8 项通过；差异检查通过。候选身份由产物中的 `code-release.json` 与 `verification.json` 固定，最终回执另行补记。

Python 全量探索执行 898 项，结果为 6 项失败、46 项错误、7 项跳过。与已有基线日志比较，未出现新的失败用例名称；这不是本次分支起点的重新执行对照，不能据此宣称全量通过。问题涉及可选依赖、私有输入、受限环境及已有配置／字号检查。正式候选使用仓库规定的固定交付门禁，单独记录结果。

本次验收还修正了保存培养推荐时误启用其他备用培养目标的问题。保存或重命名保留推荐选中的培养卡；只有主动修改某张卡的目标才把它加入培养范围。手选养成在应用和跨页恢复时不再被实际卡库覆盖；歌曲页换队会重新校验输入与参考提示，旧分享链接错误不会阻止新队伍计算。相关用例已加入固定候选门禁。

## 审阅顺序

1. 打开配队页的“卡库与队伍”，核对实际卡库与养成记录。
2. 在“日常稳分队”和培养计划间切换，确认实际值与计划值的区分是否直观。
3. 打开歌曲计算、AP 或活动工具，检查不用重选十张卡的连续操作体验。
4. 将工具推荐结果命名保存，再次应用，核对配对、队长和培养范围。
5. 用手机宽度检查浮窗、选卡和保存操作。

本地浏览器验收和候选门禁不替代用户审阅，也不代表生产环境已更新。底层计分机制仍沿用[上一阶段报告](2026-10-04-performance-team-completion-report.md)中说明的真实客户端验收边界。
